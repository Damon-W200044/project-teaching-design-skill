# 最后确认的要求

## 范围与依据

《数据可视化》以“通信运营数据分析与可视化决策平台”为背景。整改把32次按课次编写的教案重组为7个项目设计，每项目配套知识图。仅修改教学设计及对应图，原资源库、任务书、项目实施成果、客观性评价标准继续沿用；可补资源明细和教学支架，不得无依据变更总评权重。

迁移其他课程时替换课程背景与项目数。最新明确指令优先。旧附件可能写32次、8模块、“准真实数据”；不要重新带回。公开数据只能称公开数据模拟企业情境，不得称企业真实客户数据。

## 教学设计

- 一项目一份设计，可覆盖多次授课，不能机械拆成90分钟一份。
- 直接填最新学校原模板或用户确认的编辑版；保留总体目标并列栏、课上课下配对行、任务知识组块跨三行合并。尊重用户已删去的开头项目主题、活动主题与任务主题，仅保留模板字段和必要序号。
- 总目标逐项对应各活动有学习成果依据的具体最高级知识点及水平，6活动列6项；不能把6个蓝色方法框架名直接复制进来，仅满足数量不算正确。不额外列项目根节点，不列全部细目。活动序列表与活动详情中的活动目标也只写该活动这一项，格式“知识点（记忆／理解／运用）”。最高阶不等于所有目标一律运用。
- 任务知识组块只放对应图，不在图下追加知识点及水平清单。细目保存在知识图、任务描述与评价对应中，不在活动目标栏展开。能力、素质栏按原模板填写。
- 通常课上:课下为1:2；当前项目一180:360分钟，顺序先课上后课下允许。课下任务要有实际查证、编写、讨论、汇报、复核和修订工作量，不能仅改数字凑比例。若用户或实际约束另定，记录新约定；不能擅改规定课内学时。
- 教学方法保留原选项“讲授、小组讨论、答疑、实验、实训、自主学习、翻转课堂、其他”，在所用项前勾选，不删除未选项。小组讨论须在交互体现具体问题、讨论协商、结果汇报和教师反馈；按组数设计并行交流，时间闭合。
- 先决知识必须有，细化到实际所需；首活动导入必写，其他活动按需要写，无则“／”。导入注明计入哪段任务，不能重复计时。
- 地点只选课上或课下，时长只填时间。自主学习安排课下，课上独立练习按实训等实际方法表述。
- 任务描述说明“针对什么问题，采用何种策略，获得何种学习结果”；方法栏、描述与交互一致。
- 25分钟任务安排容得下的讲解、练习、讨论；60分钟可拆演示、实践、交流、汇报和修订。按目标选方法，不为凑数量堆环节。长任务可拆约15—20分钟学习环节，并非强制固定时长。
- 汇报需考虑组数，采用配对并行、代表展示或轮换；不可15分钟要求所有组逐一完整汇报。写明每组时间与覆盖机制。
- 每任务有可呈现、可检查的学习成果与匹配评价；活动总结不能代替任务成果。
- 资源按任务与情境、课件、数据和字段说明、表单和成果模板、案例或教学支架、评价反馈、工具等实际类别列，只列本任务使用部分。
- 备注是反思，不是补充教学步骤。每项目末尾仅写一次；其他任务备注空或“／”。反思写问题、处理、真实效果或证据、后续改进；没有课堂记录时标建议稿，不能虚构统计。

## 知识图

知识点是学习结果，如指标口径、需求表述要素、字段粒度辨识方法、需求覆盖检验规则。小组讨论、学生汇报、教师演示、完成一次实验是活动或方法，不直接充当知识点。

| 类型 | 图形 | 含义 |
| --- | --- | --- |
| 陈述性 DK | 矩形 | 概念、原理、公式等 |
| 程序性 PK | 圆角矩形 | 方法、操作步骤与过程 |
| 事实范例 FC | 不规则形，可用文档形 | 案例、事实、方案或产品 |
| 认知策略 CS | 圆柱 | 问题解决、学习和信息加工策略 |

无填充。红色核心知识、蓝色核心结构化框架、绿色先决知识，其他黑色。类型只用形状区分，节点不写DK/PK/FC/CS或“程序性知识”等类型标注。几何居中的核心组块可以是蓝色框架，并非必须红色。红色核心知识与蓝色框架没有天然上下位关系。

| 九类语义 | 条件与方向 |
| --- | --- |
| 各类包含 | 总到分，可具体写内容包含、步骤包含等；原则上同源同类至少2子内容，不必穷尽 |
| 组成／构成 | 分到总，组成部分须全部完整 |
| 是一种 | 下位类别到上位类别，不与包含互换 |
| 具有属性 | 事物到固有基本属性 |
| 具有特征 | 事物到固有或区分性特征 |
| 定义 | 表征概念定义；两端读成句子，方向与释义一致 |
| 并列 | 同位、独立且关联，不表示先后或上下位 |
| 是前提 | 必要先决条件到后续知识或能力 |
| 支持 | 辅助知识、策略、范例到被支持组块 |

框架与内部知识点的拆分用“内容包含”，箭头由框架到细目；不能反向标成“支持”。支持限真正辅助关系，如思政点、先决知识或范例，不能当通用兜底。素质目标中的每项思政点须用可识别的同名节点逐条进入总图及相关活动图，并建立对应关系；相关活动落实教学与评价。单个宽泛“数据诚信与责任意识”节点不能代替数据诚信、规范求证、协作担当等具体要求。关系名直接在线上标，不能只写图例，不用“相关”“关联”“掌握”等自创关系。不要求每图九类全有，也不能机械全部用支持。切分保留语义闭合，覆盖相应活动与任务；不能只有没有关系的小截图。任务图可以为完整性保留框架节点，但应区分框架与本任务新学知识。

师生交互统一采用用户参考图：①环节名 N分钟：核查或操作要求；②……；③……；问：针对本任务的具体问题；预期：可判断的回答要点。避免“15分钟学生阅读、25分钟学生查阅……”式长段记录。提问及预期回答计入已有编号环节，不额外加时。
