# 项目化教学设计与知识建模

## 执行顺序

1. 先读取用户修改稿的全部批注和圈注图；批注提取anchors为空时检查commentReference所在段落，逐项形成落实清单。核对用户本次指令与已确认的交接说明，再读取当前项目实施方案、进度表、任务书、资源和评价标准。把项目参数与沿用要求分开记录。遇到旧32次课、旧8模块等口径，以最后确认的“按7个项目分别编制”覆盖；不要据此修改其他原始文件。
2. 使用最新上传的原始模板。没有更新模板时使用 `assets/school-template.docx`；方法依据见 `assets/knowledge-model-method.pdf`（页7—17、23—30）。先读 [requirements.md](references/requirements.md)。
3. 根据项目交付任务倒推知识，建立“业务任务—知识点—学习水平—活动—任务—资源—成果—评价”对应。知识点必须是学习结果；教学方法、教师动作和活动名称不能直接冒充知识点。
4. 建立一份数据源，统一维护节点、关系、活动、任务时长、交互分段和资源；参照 `assets/project1-example.json` 的结构。该文件仅为项目一示例，不能照搬其他项目。
5. 先按课上:课下通常1:2核算时间，再写交互；当前项目一课上180、课下360分钟。用户明确另定时采用新约定。项目课上总分钟＝课上活动之和＝课上任务之和；课下分别核算；任务交互分段之和＝任务时长。课时换算读取实际课程规定。
6. 把素质目标每一项思政要求拆成可辨认的同名节点，逐项纳入总图、相关活动图并建立关系；不能仅放一个宽泛“意识”标签就认为全部落实；框架到其内部知识点用内容包含且方向为总到分，不能把内部拆分反向写支持。支持只在确实成立的辅助关系使用，例如思政、先决知识或辅助范例，不因不确定而滥用。先绘项目总图，再切分活动图和任务组块。总图核心居中，其余组块环绕；统一节点ID保持切分前后的名称、形状、关系和颜色一致。读 [diagram-and-template.md](references/diagram-and-template.md)。
7. 直接在原DOCX模板填内容、复制原活动表和任务行块。保留列宽、合并单元格、栏目顺序和课上课下成对行；不要重建近似模板。知识目标写“知识点（记忆／理解／运用）”。总目标按活动数逐项列出各活动的具体最高级知识点及水平，6活动就6项；不能只把六个蓝色方法框架名称复制进目标栏凑数量。依据实际成果选取知识点并记录学习水平证据，不额外列项目总根节点；活动序列表和活动表也只列该活动这一项，不展开全部细目。任务知识组块单元格仅放图，不重复列知识点清单；先决知识另列。
8. 尊重用户已删去的项目、活动、任务主题标题，只保留模板字段与必要序号；不能在开头或各活动任务处重新补主题名。教学方法保留全部原选项，在所用项前勾选，其他栏按实际填写；师生交互按用户参考图写“①环节名 N分钟：具体行动；②……；问：……；预期：……”，避免无编号的长篇时间流水账；课下写学生核查、修订、复核、提交，教师课后按材料反馈，不假写全程在线。选小组讨论须有讨论、学生汇报及反馈。分类且具体填写资源。内部可用ID，交付表必须显示类别、实际名称、位置或使用部分；只引用能提供或访问的材料。每任务均有成果与评价，沿用原评价标准和权重。
9. 各任务备注可空或“／”，每项目仅在末尾写一次整体反思。不编造课堂观察、完成率或改进效果；无实施记录时标建议稿或待实施补充。
10. 核对数据与结构，将最新DOCX渲染为PDF并逐页检查PNG；同步图PDF、原生可编辑VSDX与所需PNG。按当前环境的文档/PDF/持久化规范保存，报告真实验证范围，不把临时绝对路径写死。

## 核对工具

运行 `scripts/audit_design.py DATA.json --class-minutes N --home-minutes M --core NODE_ID` 检查时间、资源引用、知识类型、语义、连通及总图中心位置。它不替代专业语义判断与视觉检查。保存总图及各图的 `pos`、`W`、`H` 坐标。

针对内置学校模板运行：

```bash
python scripts/audit_template.py assets/school-template.docx OUTPUT.docx \
  --profile assets/template-profile.json --task-counts 2 2 2 2 2 2
```

将数量换成本项目实际任务数量；模板profile包含末表一次备注行。换模板时重新分析并更新profile，不可为通过检查而改原模板。脚本比较表格网格、gridSpan和vMerge。

## 复用边界

目标选取、思政逐项入图和交互样式先读 [goals-ideology-interaction.md](references/goals-ideology-interaction.md)，并查看assets/interaction-reference.png。读 [replacement-fields.md](references/replacement-fields.md) 明确替换参数；读 [pitfalls.md](references/pitfalls.md) 避免模板、图、时长和版本问题。

仅做本次授权项目。项目一已有样稿不等于已验收全部细节，也不等于授权自动做完项目二至七。用户明确要求继续时直接推进资料核对、设计、绘图和验证，不重复询问已确认事项。

## 交付门槛

- 项目名称、学时和活动任务数量来自当前资料，冲突有说明。
- 知识图有真实知识及先决知识，语义逐线可读、方向正确、无孤立节点，总图核心居中。
- 以用户最新编辑版版式为准，保留其删除的标题/任务知识文字和全量方法选项；各活动只一项有成果依据的具体知识目标，总目标项数等于活动数；不得仅复制蓝色框架标题；思政要求逐条可在图中定位；交互有编号环节、具体问题及预期回答；时间默认1:2且计算闭合。
- 每项目只有一次反思，未在每个活动末尾保留“反馈占位语”。
- Word/PDF是同一次最终渲染；VSDX含原生节点、文字与线并做打开或导入检查。未做原生Visio验证时说明验证方式。
- 不以项目一的页数、6活动、12任务、180／360分钟或19图作为其他项目标准。
